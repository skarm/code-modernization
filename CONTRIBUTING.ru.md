# Участие в разработке

[English](CONTRIBUTING.md) | **Русский**

Для локальной разработки нужны Node.js 20+, npm и Git. Для упаковки релиза
также нужен `tar` (Linux/macOS). Сборки JavaScript нет: исходники — ESM-модули.

```bash
npm ci --ignore-scripts --bin-links=false
npm run check
npm test
```

Тесты используют временные каталоги и локальные HTTP/SSE-порты. Они не требуют
входа в Codex, API-ключей или модельных вызовов. Подробности и ограничения —
в [docs/TESTING.md](docs/TESTING.ru.md).

Перед коммитом выполните `npm run scan:secrets`. Для этой команды отдельно установите
Gitleaks 8.30.1 или задайте `GITLEAKS_PATH` на его исполняемый файл. Проверяются файлы
будущего коммита и существующая Git-история; локальные игнорируемые файлы исключены.
Вывод маскирует секреты. CI запускает ту же проверку с закреплённым Gitleaks и полной
историей checkout.

В pull request опишите проблему, изменение поведения и выполненные проверки.
Для исправления ошибки добавьте проверку воспроизводящего её сценария.
Сохраняйте согласованность skills, контрактов в `references/`, примеров и runtime.
Изменения зависимостей сопровождайте обновлением `package-lock.json`.

По умолчанию документация, примеры, подписи интерфейса и справка команд пишутся
на английском. Русские переводы размещайте в соответствующих `*.ru.md` и добавляйте
ссылки между языковыми версиями. Основной источник — английский документ без языкового
суффикса. При изменении описанного поведения обновляйте обе версии. Общение навыков
по-прежнему следует языку пользователя; сохраняйте идентификаторы, ключи схем и исходные
свидетельства.

Не добавляйте результаты работы с реальными проектами, учётные данные, локальные
пути, сырые журналы SDK или архивы релизов. Для примеров используйте синтетические
данные. Замороженный эталон `tests/fixtures/proof-pack-upstream.json.gz` — часть
тестового контракта; его происхождение описано в [tests/fixtures/README.md](tests/fixtures/README.md).

Сохраняйте Apache-2.0, SPDX-заголовки и атрибуцию перенесённых исходников.
При добавлении стороннего кода обновляйте [NOTICE](NOTICE) и сведения о лицензии.

Подготовка архива описана в [docs/RELEASING.md](docs/RELEASING.ru.md).
