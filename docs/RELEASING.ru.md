# Подготовка релиза

[English](RELEASING.md) | **Русский**

Плагин распространяется исходниками и архивом для локального marketplace. `private: true`
в `package.json` защищает от случайного `npm publish`; распространение по Apache-2.0 разрешено.

## Подготовка

Имя и версия в `package.json` определяют имя архива. При изменении версии согласуйте
`package-lock.json` (корень и `packages[""]`), оба манифеста плагина, `runtime/version.mjs`
и указание текущей версии в обоих README. Сохраняйте атрибуцию и сведения об изменениях
в [NOTICE](../NOTICE).

Основные пути документов без языкового суффикса содержат английский текст, переводы —
в `*.ru.md`. При изменении поведения обновляйте обе версии. Примеры конфигурации
размещайте в `examples/`.

```bash
npm ci --ignore-scripts --bin-links=false
npm run scan:secrets
npm test
npm run doctor
npm run pack:release
```

Для сканирования нужен Gitleaks 8.30.1 в PATH либо `GITLEAKS_PATH`. Охват и ограничения
проверок описаны в [TESTING.md](TESTING.ru.md).

## Проверка архива

`pack:release` создаёт `dist/<package-name>-<package-version>.tar.gz` и `.sha256`.
Состав определяется списком `files` в `package.json` с обязательным включением манифеста
пакета, корневого lockfile и README. Включены оба языка документации. Учётные данные,
символьные ссылки, локальные зависимости и IDE-файлы исключены; заголовки ustar не
содержат личных данных владельца и метаданных файловой системы.

```bash
release_name=$(node -p "const p = require('./package.json'); p.name + '-' + p.version")
cd dist
# Linux:
sha256sum --check "$release_name.sha256"
# macOS:
shasum -a 256 --check "$release_name.sha256"
tar -tzf "$release_name.tar.gz"
```

Распакуйте в отдельную папку, затем выполните в ней
`npm ci --ignore-scripts --bin-links=false`, `npm run check`, `npm test` и `npm run doctor`.
Обычный `npm pack` исключает корневой lockfile и не заменяет этот дистрибутив.

CI запускает тесты на Linux с Node 20/22/24/26 и macOS с Node 24. Задание упаковки
проверяет контрольную сумму, устанавливает и тестирует распакованную копию и сохраняет
`verified-release-archive`. Сканер секретов проверяет исходники и полную Git-историю.
CI не обращается к реальной модели.

## Публикация

Дождитесь успешного выполнения всех заданий CI для публикуемого коммита. Включите
и проверьте приватные сообщения об уязвимостях, как описано в [SECURITY.md](../.github/SECURITY.ru.md).

Публикация исходников не требует релиза. Если создаёте релиз, явно выберите тег на
проверенном коммите и приложите архив с контрольной суммой из его CI-запуска. CI не
создаёт теги и релизы автоматически. Поддерживайте актуальные адреса репозитория и контакты.

Не включайте в исходники `dist/`, сырые журналы, личные настройки и workspace модернизации.
Сохраняйте LICENSE, NOTICE и лицензии `assets/vendor/` в дистрибутиве.
