# Проверки

[English](TESTING.md) | **Русский**

## Локальные проверки

Нужны Node.js 20+ и npm. Для тестов упаковки также нужен `tar` (Linux/macOS).

```bash
npm ci --ignore-scripts --bin-links=false
npm run check
npm test
npm run doctor
```

Эти проверки не обращаются к модели и не требуют входа в Codex. Тесты используют
временные файлы и локальные HTTP/SSE listeners на `127.0.0.1`. Полный набор запускайте
в среде, разрешающей loopback-порты; `listen EPERM` означает неуспешную проверку.

Для отдельного набора:

```bash
npm run test:proof
npm run test:ui
node --test tests/interface.test.mjs
```

## Что подтверждают проверки

- `check` проверяет JSON, согласованность пакета и зависимостей, навыки, роли, workflow,
  относительные Markdown-ссылки и синтаксис JavaScript. Это не официальный валидатор хоста.
- Workflow/engine-тесты используют SDK doubles для проверки состояния, write scopes,
  gates, отмены и продолжения. Они не оценивают качество ответов модели.
- Proof/comparator-тесты используют реальные файлы и 260 замороженных случаев исходного
  evaluator. Проверяются вердикты, отчёты раннеров, трассировка правил, fresh inputs,
  canary и семантика сравнений. См. [происхождение фикстур](../tests/fixtures/README.md).
- UI/lifecycle-тесты используют локальные процессы и HTTP/SSE-запросы. Они не подтверждают
  отрисовку в настоящем браузере или установку в конкретном клиенте Codex.
- `doctor` проверяет импорт закреплённого SDK и создание клиента. Он не проверяет вход
  или загрузку доверенных hooks хостом.

## Совместимость установки

Сохраняйте `--bin-links=false` при установке в каталог плагина: в Codex CLI 0.164.0
наблюдался отказ при вычислении отпечатка из-за ссылки `node_modules/.bin/codex`.
SDK запускает закреплённый CLI-пакет напрямую. См. [установку](../README.ru.md#установка-sdk-и-плагина).

CLI и SSH используют текстовый статус; локальная браузерная панель требует GUI-хоста
или явного `--interface gui`. Hooks должны пройти штатный review/trust хоста.
Установку и загрузку hooks проверяйте отдельно в конкретном клиенте;
см. [поведение интерфейса](../references/UI.md).

## Секреты и дистрибутив

Отдельно установите Gitleaks 8.30.1 или задайте `GITLEAKS_PATH`, затем выполните:

```bash
npm run scan:secrets
npm run pack:release
```

Сканер проверяет файлы будущего коммита и существующую локальную Git-историю,
исключает игнорируемые локальные файлы и маскирует находки. Чистый результат не
доказывает отсутствие всех возможных секретов. Проверки упаковки контролируют состав,
lockfile, лицензии и отказ от символьных ссылок и учётных данных. CI также устанавливает
и тестирует распакованный архив. См. [подготовку релиза](RELEASING.ru.md).

## Добровольный живой SDK smoke

После настройки локального входа в Codex:

```bash
npm run smoke:sdk -- --confirm-live
```

Это два реальных обращения к модели с расходом лимитов выбранного входа. Проверяются
structured output, создание/продолжение потока и сохранение синтетической фразы.
Без `--confirm-live` обращений нет. Успешный smoke не проверяет все workflow,
изоляцию sandbox или реальную миграцию. Не публикуйте сырой вывод с thread IDs.
